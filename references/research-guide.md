# 調査ガイド（Web検索の進め方）

## 情報源の信頼度の序列

上位のものを優先し、下位は補完として使う。レポートの「参考情報源」には可能な限り上位の情報源を挙げる。

1. **公式一次情報**: 公式サイト、プライバシーポリシー、利用規約、DPA（データ処理契約）、セキュリティホワイトペーパー、Trust Center / Security ページ、公式ヘルプ・ドキュメント、公式ブログ
2. **認証機関・公的機関**: ISMS認証登録簿（ISMS-AC等）、SOC2レポートの公表情報、Pマーク付与事業者検索、個人情報保護委員会・IPA等の公表資料
3. **信頼できる報道**: 大手報道機関・専門メディアによるインシデント報道
4. **二次情報**: 比較サイト、ブログ記事、フォーラム。一次情報が見つからない場合の手がかりとしてのみ使い、これ単独で「低リスク」判定の根拠にしない

## 検索クエリのパターン

サービス名をあてはめて検索する。1回の検索で答えが出ない項目は、英語クエリへの切り替えや公式ドメイン内のページ（Trust Center等）のweb_fetchを試す。

| 調査対象 | クエリ例 |
|---|---|
| 運営元 | `[サービス名] 運営会社 本社` / `[サービス名] company headquarters` |
| インシデント履歴 | `[サービス名] データ漏洩` / `[サービス名] data breach incident` |
| プライバシーポリシー | `[サービス名] privacy policy` |
| データ保持・削除 | `[サービス名] data retention deletion export` |
| 第三者認証 | `[サービス名] SOC2 ISO27001 ISMS Pマーク` |
| 事業継続性 | `[運営会社名] 従業員数 設立` / `[運営会社名] funding 資金調達` / `[サービス名] SLA uptime` |
| サポート体制 | `[サービス名] サポート 日本語` / `[サービス名] support plan SLA` |
| データ所在地 | `[サービス名] data residency` / `[サービス名] サーバー 所在地` |
| 認証機能 | `[サービス名] SSO SAML MFA 2FA` |
| 監査ログ | `[サービス名] audit log` |
| AI学習利用 | `[サービス名] AI training opt out` |

## 政府開示義務の確認

運営元の所在国が判明したら、その国の法制度によるデータ開示義務を確認する。代表例:

- **中国**: 国家情報法（2017年）により、組織・個人に国家の情報活動への協力義務。中国企業運営のサービスは原則この観点で高〜中リスク評価とする。
- **米国**: CLOUD Act により、米国企業は保存場所を問わずデータ提出命令の対象になりうる。FISA 702条も対象。ただし米国主要SaaSは企業利用が広く一般化しており、扱うデータ区分に応じて中リスク（条件付き）評価が標準的。
- **日本・EU（GDPR適用国）**: 相対的に低リスク。ただしEU企業でも米国子会社経由のデータ処理がある場合は注記する。

国の法制度は「その国に本社がある」だけで機械的に高リスクとせず、扱うデータ区分・データ所在地・企業の透明性レポートの有無と合わせて総合評価する。

## 調査時の注意

- **プラン差分に注意**: 「SSO対応」と書かれていてもEnterprise限定のことが多い。どのプランで使える機能かを必ず確認し、評価対象プランで使えない機能は「対応」と書かない。
- **買収・社名変更に注意**: サービスが買収されている場合、現在の親会社・データ管理主体を確認する。
- **検索結果の日付を確認**: 認証は失効・返上されることがある。2年以上前の情報しかない項目は「最終確認: YYYY年時点の情報」と注記する。
- **否定の証明はできない**: 「インシデント報道が見つからない」ことは「インシデントがない」ことの証明ではない。「調査時点で重大インシデントの公表・報道は確認されず」という表現を使う。
